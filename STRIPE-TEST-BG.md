# Корен — тестови онлайн плащания с Stripe (Mac)

Този проект добавя **тестово** плащане с карта през Stripe Checkout. Начинът **„Плащане при доставка“** остава наличен. Не изпращай своите `sk_test_`, `sk_live_` или `whsec_` ключове в чат, GitHub или публични файлове.

## 1. Създай собствен Stripe акаунт

Отвори https://dashboard.stripe.com/register, влез в Dashboard и активирай **test / sandbox mode**. В страницата за тестови API ключове открий **Secret key**, който започва с `sk_test_`. Ключът `pk_test_` НЕ е нужен — Stripe Checkout се създава само от backend-а.

## 2. Инсталирай Stripe CLI (еднократно)

```bash
brew install stripe/stripe-cli/stripe
stripe login
```

При `stripe login` потвърди достъпа до акаунта през браузъра.

## 3. Отвори ДВА прозореца на Terminal

**Прозорец 1** — отвори папката на проекта и изпълни:

```bash
cd ~/Downloads/koren-grocery
./stripe-listen.command
```

CLI ще покаже ред с webhook подписващ ключ, започващ с `whsec_`. Копирай го. Остави прозореца отворен — той препраща събитията от Stripe към локалния магазин на порт 8080. При ново `stripe listen` провери дали не се е сменил този ключ.

**Прозорец 2** — в папката на проекта изпълни:

```bash
cd ~/Downloads/koren-grocery
./stripe-test.command
```

Скриптът ще поиска `sk_test_...`, `whsec_...` и твоята администраторска парола (ако не е зададена като променлива). Въведи секретите само в Terminal. Те не се записват автоматично във файлове.

## 4. Пробвай поръчка

Отвори http://127.0.0.1:8080 → сложи продукт в количката → поръчка → **„Плащане с карта (ТЕСТОВ РЕЖИМ)“**. Ще се отвори официалната тестова Stripe Checkout страница.

Тестова карта (няма реално теглене на пари):

- Номер: `4242 4242 4242 4242`
- Валидност: който и да е бъдещ месец/година
- CVC: произволни 3 цифри
- Име / пощенски код: примерни данни

След плащане Stripe те връща в магазина. Сайтът проверява състоянието на поръчката, което се обновява **само от подписания Stripe webhook**. При успешен webhook покупката се маркира като „Платена“ в http://127.0.0.1:8080/admin.

Ако затвориш Stripe CLI, webhook потвържденията няма да стигат до локалния магазин. Стартирай CLI преди тестовете. Не повтаряй неясна поръчка, докато не провериш нейния статус.

## Ако опцията за карта не се появява

- Увери се, че стартираш през `./stripe-test.command`, а не през `./start-mac.command`.
- Увери се, че `stripe listen` работи и копираният `whsec_` ключ е от **текущата** CLI сесия.
- Провери, че си в тестов режим и `sk_test_` ключът е от **същия Stripe акаунт**.
- Ако порт 8080 е зает, спри предишния сървър с `Control + C` и стартирай тестовия скрипт отново.

## Актуализиране на съществуващия Корен

**Запази текущата `.data/` папка и своята база данни!** Спри сървъра (`Control + C`), направи резервно копие на папката `koren-grocery`, после прехвърли всички нови файлове от ZIP архива в съществуващата папка, *без* да изтриваш `.data/`. ZIP архивът НЕ включва `.data/` и няма да презапише съществуващите поръчки или продукти. Старият стартов скрипт е запазен.

## Преди реални онлайн продажби

Настрой Stripe бизнес акаунт, фирмени данни и банкова сметка. Публикувай магазина на надежден хостинг с HTTPS и създай **отделен публичен** Stripe webhook endpoint: `https://твоят-домейн/api/stripe/webhook`. За него се използва **негов собствен** `whsec_` ключ; локалният `whsec_` от Stripe CLI НЕ е подходящ за публичния сървър. В продукцията задай `sk_live_` през защитени променливи на хостинга и `APP_BASE_URL` с HTTPS домейн. НЕ използвай `stripe-test.command` за реални транзакции.

Задължителни допълнителни стъпки: периодично сверяване на изоставени checkout сесии и webhook събития; преглед на поръчки със статус „Проверка на плащане“; логове и наблюдение, архивиране, защита срещу автоматизирани поръчки, GDPR/правни документи и правила за доставки и онлайн търговия с храни. Няма внедрено автоматично възстановяване на суми; платена поръчка не може да бъде отменена от админа, преди да бъде уредено възстановяването на плащането. Тази версия е **за локално тестване, не за продукционен публичен хостинг**.
